## Background

`entries` has `id`, `key`, `body`, `body_hash`, `source`, `created_at`,
`updated_at`. No expiry. `user_version` is **1**. List/search return every
row. `store_add` keyless-merges on body hash (including rows the user would
rather forget). Public process exits are **0 / 1 / 2 only**.

Memories are durable by default. Some captures are temporary (tickets,
WIP, “remind me this week”). There is no way to mark that or to hide
them after a date without `delete`.

## Problem

Need optional time-to-live that:

1. Defaults to **no expiry** (durable).
2. Hides expired rows from normal list/search/get (virtual **trash**).
3. Lets the user **restore** (clear expiry) or **delete forever**.
4. Revives an expired row on a new `add` of the same keyless body (keep id).
5. Works for CLI, agents, and the Mac shell (submodule first).

Not a sync/TTL-across-devices problem. Not automatic silent GC.

## Questions and Answers

### Round 1 — product (Itay, 2026-08-24)

- **Q: Default TTL?**  
  A: **None.** Omit expiry unless the writer sets it.

- **Q: Who may set expiry?**  
  A: **All surfaces** — human CLI, agents, Mac add/edit/share.

- **Q: Flag shape?**  
  A: **Both.** `--ttl` relative, `--expires` absolute.

- **Q: List/search after expiry?**  
  A: **Excluded by default.** Expired rows are trash.

- **Q: Delete expired automatically?**  
  A: **No.** Treat as a virtual trash bin: search trash, restore (clear
  expiry), or permanently delete. Settings (and CLI) can empty trash.

- **Q: `get` of an expired id?**  
  A: **New error “expired”.** `--trash` on list / search / get reads trash.

- **Q: GC policy?**  
  A: **Hide** by default; actual delete only when the user asks.

- **Q: Keyless `add` of a body that exists only as trash?**  
  A: **Revive** — same id, clear expiry (or apply a new one if the add
  sets `--ttl`/`--expires`), merge tags, bump `updated_at`.

- **Q: `update` expiry without touching body/tags?**  
  A: **Yes** — set or clear.

- **Q: CLI vs Mac order?**  
  A: **CLI submodule first** (schema + flags + tests), then remember-mac.

- **Q: Mac UI?**  
  A: **Both** — expiry on add/edit, indication that a live item is
  temporary, trash browsing, restore, empty-trash in Settings.

### Round 2 — contract details (locked with the Round 1 answers)

- **Q: New process exit code for expired?**  
  A: **No.** Foundations lock **0 / 1 / 2**. `get` of an expired row
  **without** `--trash` is **exit 1**, stderr token **`expired`**
  (prefixed `remember: ` like other errors). Exit **2** stays true
  not-found. Agents: 2 → missing; 1 + `expired` → pass `--trash` or
  restore. JSON is not emitted on this failure (same as other errors).

- **Q: `--ttl` grammar?**  
  A: One token `<unsigned-int><unit>` with unit **`m` / `h` / `d` / `w`**
  (minutes, hours, days, weeks). Examples: `30m`, `12h`, `7d`, `2w`.
  No bare integer. `0` invalid. Computed **at write time** from `utc_now`
  and stored as absolute `expires_at` (same ISO-8601 UTC `.mmmZ` as
  `created_at`).

- **Q: `--expires` grammar?**  
  A: Absolute UTC. `YYYY-MM-DD` → that calendar day **23:59:59.999Z**.
  Full `YYYY-MM-DDTHH:MM:SS.mmmZ` accepted as-is (must already be UTC `Z`).
  Past timestamps are allowed (the row is born in trash).

- **Q: `--ttl` and `--expires` together?**  
  A: **Usage error.** At most one.

- **Q: `--trash` semantics?**  
  A: **Only trash** (expired: `expires_at` not null and `<= now`). Default
  list/search/get/tags: **active only** (`expires_at` null **or** `> now`).
  No “include both” flag in v1.

- **Q: Empty trash CLI?**  
  A: New command **`purge-trash`**: permanently delete every expired row
  (one write txn, FTS + tag GC). No prompt (Settings UI confirms). Human
  stdout: count of deleted ids (or JSON envelope `action:deleted`,
  `count`, `entries` snapshots — cap snapshots if huge: JSON
  `count` + empty `entries` when over 100, plus stderr note; prefer
  returning all snapshots at personal scale ≤5k).

- **Q: `delete` of one trash row?**  
  A: Existing `delete` (locator) already permanent. Works without
  `--trash`. `get` still needs `--trash` to *read* it first.

- **Q: `tags` command?**  
  A: Counts **active** entries only. `--trash` → counts among trash only.

- **Q: Spotlight (Mac)?**  
  A: Index **active** only. Restore/expiry change → existing
  `noteChanged` / force reindex.

- **Q: JSON field?**  
  A: Always present: `"expires_at": null` or the ISO string (same null
  style as `key`).

- **Q: Update flags to change only expiry?**  
  A: `update` may use **only** `--ttl` / `--expires` / `--clear-expires`
  (at least one of those or the existing body/tag flags). `--clear-expires`
  + `--ttl`/`--expires` → usage error.

## Design

### Schema (`user_version` 2)

```sql
-- new databases: column in CREATE TABLE entries
expires_at TEXT  -- NULL = durable; otherwise ISO-8601 UTC .mmmZ

-- migrate v1 → v2 (one transaction):
ALTER TABLE entries ADD COLUMN expires_at TEXT;
PRAGMA user_version = 2;

CREATE INDEX ix_entries_expires
  ON entries(expires_at) WHERE expires_at IS NOT NULL;
```

Open: `0` → create at **2**; `1` → migrate to 2; `2` → ok; `>2` → refuse
(`database is newer than this remember`). Fresh CREATE includes
`expires_at` (do not create at v1 then migrate).

Compare expiry with the same `utc_now()` string the row stores (lexicographic
ISO order = time order). Bind `now` into list/search/get/tags SQL.

### Store port

- `Entry` gains `char *expires_at` (NULL if none). JSON/human via `output.c`.
- `STORE_ERR_EXPIRED` — get/update-by-locator found a trash row without
  trash mode. Maps to **exit 1**, message `expired`.
- `store_add`: optional `expires_at` (NULL or ISO). Keyless merge / keyed
  upsert that hits an expired row **revives**: keep id; union tags; if the
  incoming add has a new expiry use it, else set `expires_at` NULL; replace
  body on keyed upsert; bump `updated_at`.
- `ListQuery` / `SearchQuery`: `bool trash` (default false).
- `store_get` / `store_get_by_key`: `bool trash`. If `!trash` and row
  expired → `STORE_ERR_EXPIRED`. If `trash` and row **active** →
  `STORE_ERR_NOT_FOUND` (get --trash is trash-only, same as list).
- `store_update`: optional set/clear expires; still never changes `source`
  or `key`.
- `store_purge_trash(now)` → deleted snapshots + count.
- `store_tags`: honor trash flag.

### CLI

```text
remember add [--ttl 7d | --expires 2026-12-31] ...
remember update <id>|--key K [--ttl 7d | --expires ... | --clear-expires] ...
remember list|search|tags [--trash]
remember get [--trash] <id>|--key K
remember purge-trash
```

Help one-liners: expiry optional; default list hides trash; `purge-trash`
is permanent.

Skill: when to use `--ttl` (WIP, tickets); default search does not see
trash; restore with `update --clear-expires`; empty with `purge-trash`.

### Mac shell (see log 002)

Kit `Entry.expiresAt: String?`. Browse Active vs Trash. Temporary badge
when `expires_at` is in the future. Restore / Delete in trash. Settings
Empty Trash → `purge-trash`. Add/edit optional expiry.

## Examples

**Add with a week of life:**

```text
remember add --ttl 7d --tag wip "spike: try WAL"
# JSON expires_at = now + 7d
```

**List default vs trash:**

```text
remember list              # active only
remember list --trash      # expired only
remember get 42            # exit 1, stderr expired (if 42 in trash)
remember get --trash 42    # JSON of the trash row
remember update 42 --clear-expires   # restore
remember purge-trash       # delete all trash forever
```

**Revive:**

```text
remember add --tag wip "spike: try WAL"   # same body as expired
# merged/updated existing id; expires_at null; tags union
```

## Trade-offs

- **Chosen: hide, not auto-delete**  
  Pros: undo via restore; agents can still `--trash get`.  
  Cons: DB grows until empty-trash. Personal scale is fine.

- **Chosen: exit 1 + `expired`, not exit 3**  
  Pros: public 0/1/2 contract stays; agents already handle 1.  
  Cons: 1 is overloaded (usage vs expired) — token on stderr is the
  discriminant. Document in skill.

- **Chosen: store absolute `expires_at`**  
  Pros: one comparison; `--ttl` is sugar.  
  Cons: relative intent is not preserved (“7d from add”). Accepted.

- **Rejected: default TTL**  
  Second brain is durable; expiry is opt-in.

## Verification Criteria

1. New DB opens at `user_version=2` with `expires_at`.
2. v1 DB migrates to 2; existing rows have `expires_at` NULL; data intact.
3. Add without flags → `expires_at` JSON `null`; appears in default list.
4. `--ttl 1h` / `--expires 2026-12-31` stored as ISO; future rows in
   default list; past `--expires` only in `--trash`.
5. After expiry, default list/search/tags omit the row; `--trash` sees it.
6. `get` expired → exit 1, stderr contains `expired`; `--trash` → exit 0.
7. `get --trash` of an **active** id → exit 2.
8. `update --clear-expires` restores; row leaves trash.
9. Keyless add of expired body revives (same id, not trash).
10. `purge-trash` deletes only expired; FTS/tag GC consistent.
11. `--ttl` + `--expires` → exit 1 usage.
12. Mac: temporary badge; trash mode; empty trash; `just check` after pin bump.
13. Skill/help mention `--ttl` / `--expires` / `--trash` / `purge-trash`.

## Known Limitations

- No auto-purge on a timer (user/Settings/CLI only).
- No “include expired in list” mix flag.
- Date-only `--expires` is UTC end-of-day, not local tz.
- Trash is inferred from the clock, not a separate `trashed_at` column.
