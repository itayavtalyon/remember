## Background

`entries` has `id`, `key`, `body`, `body_hash`, `source`, `created_at`,
`updated_at`. No expiry. `user_version` is **1**. List/search return every
row. `store_add` keyless-merges on body hash (including rows the user would
rather forget). Public process exits today are **0 / 1 / 2**; this log **adds
exit 3 = wrong bin** (`expired` / `not_in_trash`).

Memories are durable by default. Some captures are temporary (tickets,
WIP, “remind me this week”). There is no way to mark that or to hide
them after a date without `delete`.

## Problem

Need optional time-to-live that:

1. Defaults to **no expiry** (durable).
2. Hides expired rows from normal list/search/get (virtual **trash**).
3. Lets the user **restore** (clear expiry) or **delete forever**.
4. Revives an expired row on a new `add` of the same keyless body (keep id).
5. Works for CLI, agents, and the Mac shell (submodule first).

Not a sync/TTL-across-devices problem. Not automatic silent GC.

## Questions and Answers

### Round 1 — product (Itay, 2026-08-24)

- **Q: Default TTL?**  
  A: **None.** Omit expiry unless the writer sets it.

- **Q: Who may set expiry?**  
  A: **All surfaces** — human CLI, agents, Mac add/edit/share.

- **Q: Flag shape?**  
  A: **Both.** `--ttl` relative, `--expires` absolute.

- **Q: List/search after expiry?**  
  A: **Excluded by default.** Expired rows are trash.

- **Q: Delete expired automatically?**  
  A: **No.** Treat as a virtual trash bin: search trash, restore (clear
  expiry), or permanently delete. Settings (and CLI) can empty trash.

- **Q: `get` of an expired id?**  
  A: **New error “expired”.** `--trash` on list / search / get reads trash.

- **Q: GC policy?**  
  A: **Hide** by default; actual delete only when the user asks.

- **Q: Keyless `add` of a body that exists only as trash?**  
  A: **Revive** — same id, clear expiry (or apply a new one if the add
  sets `--ttl`/`--expires`), merge tags, bump `updated_at`.

- **Q: `update` expiry without touching body/tags?**  
  A: **Yes** — set or clear.

- **Q: CLI vs Mac order?**  
  A: **CLI submodule first** (schema + flags + tests), then remember-mac.

- **Q: Mac UI?**  
  A: **Both** — expiry on add/edit, indication that a live item is
  temporary, trash browsing, restore, empty-trash in Settings.

### Round 2 — contract details (locked with the Round 1 answers)

- **Q: New process exit code for expired?**  
  A: **Yes — exit 3 = “wrong bin.”** Round 1 asked for a distinct expired
  error. A first draft stuffed that into exit 1 + stderr `expired` to avoid
  touching the v1 0/1/2 table. That overloads 1 (usage vs “this id exists
  but is in the other bin”) and forces agents to parse stderr. **Exit 3** is
  the discriminant (same role 2 has for not-found), shared by both
  bin-mismatch directions and disambiguated by the stderr token:  
  - `0` ok  
  - `1` usage / store / other errors  
  - `2` not found (no such id/key in either bin)  
  - `3` wrong bin — row exists in the other state. Token **`expired`**
    (looked in active, it's in trash → pass `--trash` or `--clear-expires`)
    or **`not_in_trash`** (looked in trash with `--trash`, it's active →
    drop `--trash`).  
  stderr carries the token (with `remember: ` prefix). No JSON envelope on
  this failure. Additive: old scripts that only special-case 2 still treat
  3 as failure. Agents: exit 3 → flip `--trash`.

- **Q: `--ttl` grammar?**  
  A: One token `<unsigned-int><unit>` with unit **`m` / `h` / `d` / `w`**
  (minutes, hours, days, weeks). Examples: `30m`, `12h`, `7d`, `2w`.
  No bare integer. `0` invalid. Computed **at write time** from `utc_now`
  and stored as absolute `expires_at` (same ISO-8601 UTC `.mmmZ` as
  `created_at`).

- **Q: `--expires` grammar?**  
  A: `YYYY-MM-DD` → **local** end-of-day (`23:59:59.999` in the caller's
  timezone), converted to UTC on save. Full `YYYY-MM-DDTHH:MM:SS[.mmm]Z`
  accepted (must be UTC `Z`). **Normalize every stored value to canonical
  `.mmmZ`** — pad/truncate fractional seconds to exactly 3 digits — so
  lexicographic order == time order; a bare-second `…:59Z` would otherwise
  sort *after* `…:59.999Z`. Past timestamps are allowed (born in trash).

- **Q: `--ttl` and `--expires` together?**  
  A: **Usage error.** At most one.

- **Q: `--trash` semantics?**  
  A: **Only trash** (expired: `expires_at` not null and `<= now`). Default
  list/search/get/tags **and the `update`/`delete` locators**: **active
  only** (`expires_at` null **or** `> now`). `--trash` flips each to
  trash-only. No “include both” flag in v1.

- **Q: Empty trash CLI?**  
  A: New command **`purge-trash`**: permanently delete every expired row
  (one write txn, FTS + tag GC). No prompt (Settings UI confirms). Human
  stdout: count of deleted ids (or JSON envelope `action:deleted`,
  `count`, `entries` snapshots — cap snapshots if huge: JSON
  `count` + empty `entries` when over 100, plus stderr note; prefer
  returning all snapshots at personal scale ≤5k).

- **Q: `delete` of one trash row?**  
  A: `delete --trash <locator>` — permanent. Like `get`/`update`, plain
  `delete` targets active only (a trash row → exit 3 `expired`); `--trash`
  targets trash only (an active row → exit 3 `not_in_trash`).

- **Q: `tags` command?**  
  A: Counts **active** entries only. `--trash` → counts among trash only.

- **Q: Spotlight (Mac)?**  
  A: Index **active** only. Mutations force a reindex; the ~3h idle sync
  also catches natural expiry (the active-row fingerprint drops), and the
  Mac forces a reindex on window activate for immediacy. A Spotlight hit
  that has since expired opens the row in **Trash** with Restore, not an
  error. (Mac detail: log 002.)

- **Q: JSON field?**  
  A: Always present: `"expires_at": null` or the ISO string (same null
  style as `key`).

- **Q: Update flags to change only expiry?**  
  A: `update` may use **only** `--ttl` / `--expires` / `--clear-expires`
  (at least one of those or the existing body/tag flags). `--clear-expires`
  + `--ttl`/`--expires` → usage error. Restore is
  `update --trash <locator> --clear-expires` (the row is in trash, so
  `--trash` is required to reach it).

### Round 4 — implementer contract (locked, 2026-08-24)

Closes remaining gaps so plan 12 can start without inventing product.
Round 2 still holds except where a bullet below **supersedes** it.

- **Q: `expires_at == now`?**  
  A: Trash. Predicate is `expires_at IS NOT NULL AND expires_at <= now`
  (lexicographic ISO). Active is `expires_at IS NULL OR expires_at > now`.
  Store tests may write `expires_at` equal to a captured `now` string.

- **Q: Past `--expires`?**  
  A: **Allowed** (born in trash). Not a usage error. Same for `--ttl`
  that overflows into the past — it can't; `--ttl` is always computed
  from write-time `now` and a positive duration.

- **Q: `--ttl` token + overflow?**  
  A: Whole token matches `^[1-9][0-9]*[mhdw]$` (no leading zeros, no
  `+`, no fraction, **lowercase** units only). `0`, `7`, `07d`, `7x`,
  `1.5d`, `1M`, `+7d` → usage exit 1. Compute `now_sec + n * unit` in
  64-bit seconds; overflow, or a UTC year outside `0001…9999`, → usage
  1. No separate product max (e.g. “10 years”).

- **Q: `--expires` accepted forms?**  
  A: Only (1) `YYYY-MM-DD` → caller-local `23:59:59.999` → UTC
  `.mmmZ` on save; (2) `YYYY-MM-DDTHH:MM:SSZ` or
  `YYYY-MM-DDTHH:MM:SS.fracZ` (`frac` 1+ digits; pad/truncate to
  exactly 3). Reject offsets (`+00:00`), missing seconds, space
  instead of `T`, date-only with `Z`, empty fraction, anything else.
  Tests that need determinism prefer form (2) or set `TZ`.

- **Q: Clock injection?**  
  A: **No function-pointer clock.** `utc_now()` stays as today. Store
  APIs that compare expiry take `const char *now` (canonical `.mmmZ`).
  CLI calls `utc_now()` **once per command** and passes it down. Store
  unit tests pass a fixture `now`. CLI tests use past/future `--expires`
  (form 2) rather than `sleep`.

- **Q: Human list / get show `expires_at`?**  
  A: **No.** Human `list`/`search` stay
  `id | key | tags | preview | updated_at`. Human `get` stays body-only.
  `expires_at` is **JSON-only** (always present, `null` or ISO). Agents
  already use `--json`.

- **Q: `purge-trash` JSON snapshot cap? (supersedes Round 2 “over 100”)**  
  A: **No cap.** Always
  `{"version":1,"action":"deleted","count":N,"entries":[…all snapshots…]}`.
  Empty trash: `count:0`, `entries:[]`, exit 0. Personal scale ≤5k;
  large JSON is accepted. Human stdout: the integer `N` (same as
  delete-one prints an id — here a count). No prompt.

- **Q: `update --trash` of a trash row without `--clear-expires`?**  
  A: Allowed. Body/tags-only → row stays in trash (expiry unchanged).
  `--ttl` / `--expires` → write the new absolute `expires_at` from this
  update; if the result is `NULL` or `> now`, the row **leaves trash**
  (restore-with-new-TTL). `--clear-expires` + `--ttl`/`--expires` still
  usage error.

- **Q: `--trash` / `--clear-expires` on `add` or `purge-trash`?**  
  A: **No.** Unknown/invalid flags → usage 1. `add` only `--ttl` /
  `--expires` (mutex). Revive of an expired keyless/keyed hit still
  happens inside `store_add` (no `--trash` on the argv).

- **Q: Who may set expiry vs Share UI? (clarifies Round 1 “all surfaces”)**  
  A: CLI / agents / Mac add+edit **ship** `--ttl`/`--expires`. The
  store does not forbid Share. The **Share compose UI field** is
  deferred (Mac log 002 / Future Work). Share keeps writing durable
  rows until that UI exists.

- **Q: FTS of expired rows?**  
  A: Rows **stay in FTS** until real `delete` / `purge-trash`. Search
  adds the same SQL bin predicate as list. Natural expiry does **not**
  rebuild FTS (`expires_at` is not indexed content).

- **Q: stderr tokens?**  
  A: Exact, same shape as `not found`: `remember: expired\n` and
  `remember: not_in_trash\n`. `store_status_message` returns `expired`
  / `not_in_trash`. No extra hint text. No JSON on the failure.
  `store_status_to_exit`: `STORE_ERR_NOT_FOUND` → 2;
  `STORE_ERR_EXPIRED` and `STORE_ERR_NOT_IN_TRASH` → **3**; else 1.
  Public enum: `REMEMBER_WRONG_BIN = 3`.

- **Q: JSON envelope version / field order?**  
  A: Stay `version: 1`. Add `"expires_at"` **after** `"updated_at"`,
  always present (`null` or the canonical ISO string).

- **Q: `purge-trash` command wiring?**  
  A: New `CLI_CMD_PURGE_TRASH` + table row. Own TU `cmd_purge.c`
  (no locator parse). Wire in `REMEMBER_LIB_SOURCES` **and** the
  `-Wcast-qual` list. Facade parity tests include it.

## Design

### Schema (`user_version` 2)

```sql
-- new databases: column in CREATE TABLE entries
expires_at TEXT  -- NULL = durable; otherwise ISO-8601 UTC .mmmZ

-- migrate v1 → v2 (one transaction):
ALTER TABLE entries ADD COLUMN expires_at TEXT;
PRAGMA user_version = 2;
-- ponytail: no expires_at index — full scan is sub-ms at <=5k rows.
-- Active filter (expires_at IS NULL OR > now) can't use one anyway;
-- add a partial `WHERE expires_at IS NOT NULL` only if trash/purge scans hurt.
```

Open: `0` → create at **2**; `1` → migrate to 2; `2` → ok; `>2` → refuse
(`database is newer than this remember`). Fresh CREATE includes
`expires_at` (do not create at v1 then migrate).

Compare expiry with the same `utc_now()` string the row stores (lexicographic
ISO order = time order). Bind `now` into list/search/get/tags SQL.

### Store port

- `Entry` gains `char *expires_at` (NULL if none). JSON always emits it
  (`output.c`); human list/get lines **do not**.
- `STORE_ERR_EXPIRED` — locator hit a trash row without `--trash`.
  **Exit 3**, message `expired`.
- `STORE_ERR_NOT_IN_TRASH` — locator hit an active row with `--trash`.
  **Exit 3**, message `not_in_trash`.
- `store_add(..., expires_at /* NULL or canonical ISO */)`: keyless merge /
  keyed upsert that hits an expired row **revives**: keep id; union tags;
  if the incoming add has a new expiry use it, else set `expires_at` NULL;
  replace body on keyed upsert; bump `updated_at`. Does not take a trash
  flag (add always addresses the row by hash/key).
- `ListQuery` gains `bool trash` (default false). `store_list` /
  `store_search` / `store_tags` take `const char *now` and filter the bin.
- Locator ops take `bool trash` **and** `const char *now`:
  `store_get` / `store_get_by_key` / `store_update` / `store_delete_*`.
  `!trash` + expired → `STORE_ERR_EXPIRED`; `trash` + active →
  `STORE_ERR_NOT_IN_TRASH`; missing in both bins → `STORE_ERR_NOT_FOUND`.
- `store_update`: independent `set_expires` flag (same shape as
  `set_body` / `set_tags`): `set_expires=false` leaves expiry alone;
  `set_expires=true` + `expires_at=NULL` is `--clear-expires`;
  `set_expires=true` + ISO string writes that value. Still never
  changes `source` or `key`. CLI requires at least one of body / tags /
  expires. Restore = `trash` + clear expires. `--trash` + new future
  `--ttl`/`--expires` also leaves trash.
- `store_purge_trash(now)` → all expired snapshots + count (one write
  txn, FTS delete + tag GC). Expired rows remain in FTS until this or
  a single `delete`.
- `store_status_to_exit`: not-found → 2; expired / not-in-trash → 3;
  else 1.

### CLI

```text
remember add [--ttl 7d | --expires 2026-12-31] ...
remember update [--trash] <id>|--key K [--ttl 7d | --expires ... | --clear-expires] ...
remember delete [--trash] <id>|--key K
remember list|search|tags [--trash]
remember get [--trash] <id>|--key K
remember purge-trash
```

Help one-liners: expiry optional; default list hides trash; `purge-trash`
is permanent. Public exits in `--help`: `0/1/2/3`.

Skill: when to use `--ttl` (WIP, tickets; computed from **write** time —
`update --ttl 7d` is 7d from the update, not from creation); default search
does not see trash; restore with `update --trash --clear-expires`; empty
with `purge-trash`; exit 3 = `expired`/`not_in_trash` → flip `--trash`.
Human list format unchanged; read `expires_at` from `--json` only.

### Mac shell (see log 002)

Kit `Entry.expiresAt: String?` + `trash` flag on locators. Browse Active vs
Trash. Temporary badge when `expires_at` is in the future ("expires soon"
if ≤24h; recomputed on window show). Restore (`update --trash
--clear-expires`) / Delete (`delete --trash`) in trash. Settings Empty Trash
→ `purge-trash`. Add/edit optional expiry (date = local EOD → UTC).

## Examples

**Add with a week of life:**

```text
remember add --ttl 7d --tag wip "spike: try WAL"
# JSON expires_at = now + 7d
```

**List default vs trash:**

```text
remember list              # active only
remember list --trash      # expired only
remember get 42                        # exit 3, stderr expired (42 in trash)
remember get --trash 42                # JSON of the trash row
remember update --trash 42 --clear-expires   # restore
remember delete --trash 42             # delete one trash row forever
remember purge-trash                   # delete all trash forever
```

**Revive:**

```text
remember add --tag wip "spike: try WAL"   # same body as expired
# merged/updated existing id; expires_at null; tags union
```

## Trade-offs

- **Chosen: hide, not auto-delete**  
  Pros: undo via restore; agents can still `--trash get`.  
  Cons: DB grows until empty-trash. Personal scale is fine.

- **Chosen: exit 3 = wrong bin (both directions)**  
  Pros: machines branch without parsing stderr; not-found (2) stays “no such
  id”; usage (1) stays usage; one code covers `expired` and `not_in_trash`
  (token gives direction) instead of a fourth exit.  
  Cons: v1 docs/skill said 0/1/2 only — this is an additive public code.
  Old agents that treat any non-zero except 2 as “error” still behave.

- **Chosen: store absolute `expires_at`**  
  Pros: one comparison; `--ttl` is sugar.  
  Cons: relative intent is not preserved (“7d from add”). Accepted.

- **Rejected: default TTL**  
  Second brain is durable; expiry is opt-in.

## Verification Criteria

1. New DB opens at `user_version=2` with `expires_at`.
2. v1 DB migrates to 2; existing rows have `expires_at` NULL; data intact.
3. Add without flags → `expires_at` JSON `null`; appears in default list.
4. `--ttl 1h` / `--expires 2026-12-31` stored as canonical `.mmmZ`
   (date-only = local end-of-day → UTC); future rows in default list;
   past `--expires` only in `--trash`. Bare-second `…:59Z` → `…:59.000Z`.
5. After expiry, default list/search/tags omit the row; `--trash` sees it.
6. `get` expired → **exit 3**, stderr contains `expired`; `--trash` → exit 0.
7. `get`/`update`/`delete --trash` of an **active** id → exit 3, stderr
   `not_in_trash`.
8. `get`/`update`/`delete` of an **expired** id without `--trash` → exit 3,
   stderr `expired`.
9. `update --trash <id> --clear-expires` restores; row leaves trash.
   `update --trash <id> --ttl 7d` also leaves trash when the new expiry
   is in the future.
10. Keyless add of expired body revives (same id, not trash).
11. `purge-trash` deletes only expired; FTS/tag GC consistent; empty →
    count 0 exit 0; JSON includes every snapshot (no cap).
12. `--ttl` + `--expires` → exit 1 usage. Invalid/overflow `--ttl` → 1.
13. `expires_at == now` is trash. Human list columns unchanged.
14. Mac: temporary badge; trash mode; empty trash; `just check` after pin bump.
15. Skill/help mention `--ttl` / `--expires` / `--trash` / `purge-trash`
    and exit **3**.

## Known Limitations

- No auto-purge on a timer (user/Settings/CLI only).
- No “include expired in list” mix flag.
- Date-only `--expires` is **local** end-of-day → UTC on save; full `…Z` is
  taken as absolute UTC.
- No `expires_at` index (see schema note); fine at personal scale.
- Spotlight can lag natural expiry by up to the ~3h idle-sync window (or
  until the next mutation / window activate); acceptable, not real-time.
- Trash is inferred from the clock, not a separate `trashed_at` column.
- Human list/get do not print `expires_at` (JSON only).
- No production clock port; store tests pass fixture `now`.
- Share compose UI expiry is Mac-deferred; CLI flags still exist.

## Implementation Results

**Shipped (CLI, 2026-08-24, plan 12):** `user_version` 2 with `expires_at TEXT` and no index. v0 creates at 2; v1 migrates in the same write-lock transaction as create. Store locators/list/search/tags take `now` + bin; `expires_at == now` is trash. `store_add` revives expired keyless/keyed hits. `store_purge_trash` returns every snapshot (no cap). Public exits 0/1/2/3; stderr `remember: expired` / `remember: not_in_trash`. JSON `"expires_at"` after `"updated_at"`. `--ttl` / `--expires` / `--clear-expires` / `--trash` / `purge-trash` as specified.

**Deviation (documented, not invented product):** an `add` that hits an *active* row (keyless merge or keyed upsert) does not apply incoming `expires_at`. Only insert and revive write expiry. Changing TTL on an existing active row is `update --ttl`/`--expires`.
