# Plugin trust

Status: how `remember` records that a person allowed a plugin or a hook, and refuses to run code whose hash changed. The file is `<data dir>/trust.json`. The code is `src/plugin_trust.c`; the CLI's confirm function is `cli_confirm_typed_name` in `src/cli.c`. The commands that call it (`plugin add`, `plugin hook`, `plugin trust`) are plan 34, and the runs that check it are plans 35 and 36. Until those plans merge, the only caller in a release build is `settings set plugin.<name>.enabled true`.

Decisions are `decision:…` entries tagged `subject:plugins`: `decision:2026-11-12-trust-file`, `decision:2026-11-11-trust-file`, `decision:2026-11-12-plugin-approval-required-exit-5`, `decision:2026-11-12-hook-approval-required-exit-5`, `decision:s-05`, `decision:g-29`, `decision:g2-09`, `decision:g2-11`, `decision:g2-13` and the plan 33 coder grill (`decision:2026-11-22-plan33-…`, named below). Sentences are quoted from the approved copy C-15, C-16 and C-17 (`decision:2026-11-12-copy-batch-e3b-warning-splits` entry 11).

Items marked **OPEN** have no approved copy. The code does what this spec says for them, and a later answer replaces it. They are listed in [Open](#open).

## The file

`decision:2026-11-12-trust-file`, `decision:g2-09`.

- The path is `<data dir>/trust.json`. The data dir is the one of `brains.json` (`decision:g-01`). The caller passes it; the module reads no environment variable. There is no `<data dir>/plugins/trust.json` and no `<plugins dir>/trust.json`.
- The mode is `0600`. There is no HMAC. Trust uses no Keychain, libsecret or polkit.
- The document is one JSON object, ending with one newline:

```json
{"format":"remember-trust","version":1,"entries":[{"kind":"plugin","name":"wake","path":"/data/plugins/wake","folder_sha256":"…","manifest_sha256":"…","files":[{"path":"/data/tools/tool.sh","sha256":"…","size":10,"mtime":1700000000}],"interpreter":null,"needs":["body","links"],"trusted_at":"2026-11-22T10:00:00.000Z","dev":false}]}
```

- `kind` is `plugin` or `hook`. `name` is unique in the file, across both kinds. `path` is the plugin folder, or the hook's command path (`argv[0]` of its one command). `files` holds at most 8 rows. `interpreter` is `null` or `{"path","sha256"}`. `size` is bytes and `mtime` is seconds since the epoch, both whole numbers. `trusted_at` is the time the caller passed.
- A write takes a lock (`<data dir>/trust.json.lock`, a POSIX record lock, waited for at most 2 s, then status busy), reads the file again, replaces the entry of that name or adds one, writes `trust.json.tmp` with `O_EXCL` after unlinking any stale one, flushes it to disk, and renames it over `trust.json`. `trust.json` is never written in place (`decision:2026-11-22-plan33-trust-lock`).
- A file that cannot be used is **unreadable**: not a regular file, not owned by the effective user, writable by group or others (the rule ssh applies to its own files, `decision:2026-11-23-plan33-trust-json-owner-mode`), over 1 MiB, not this document (any other member, a member given twice, a wrong type, a hash that is not 64 lowercase hex digits, more than 8 `files` rows, a negative `size`), more than 1024 entries, or two entries with one name. It is read with `O_NONBLOCK` and an `fstat`, so a FIFO cannot hang it. Every check against it says untrusted, every write against it fails, and the file is never written over (`decision:2026-11-22-plan33-trust-json-unreadable`). A file that is absent, or whose folder is missing, is an empty document.

## The hash

`decision:2026-11-12-trust-file`, `decision:g-29`, `decision:2026-11-22-plan33-folder-hash`, `-hash-caps`, `-many-entries`, `-argv-paths`.

- `folder_sha256` is the SHA-256 of one record for each regular file under the plugin folder, in the byte order of the relative path: `F`, `x` (the owner's execute bit is set) or `-`, the 64 hex digits of the file's SHA-256, the relative path, and a NUL. Only regular files count. A symlink (the folder itself included), FIFO, device, socket or unreadable entry anywhere makes the code unhashable.
- `manifest_sha256` is the SHA-256 of the plugin.json bytes the caller parsed the commands and needs from (`PluginTrustSubject.manifest`, at most 65536 bytes; `plugin_trust_load_installed` reads them once from `<folder>/plugin.json`), never of a second read of the file, so a plugin.json swapped after the parse cannot pass a check for the argv the caller will run. Then, for each command that runs `<shell> -c <inline>` (`sh`, `bash` or `zsh`, directly or after `env`), a NUL, `sh-c`, a NUL, the inline text and a NUL.
- `files` holds `command[0]` and every later argv item of every command, in command order then argv order, that names an existing regular file, one row for each distinct realpath. A relative `command[0]` is looked up against the plugin folder (R2.8's base). A relative later item is looked up in the folder the command runs in, `PluginTrustCommand.cwd`: an absolute path, or NULL for the plugin folder (`decision:2026-11-23-plan33-argv-cwd`). Plan 34 fills it from a hook's `working_directory`; a relative `cwd` makes the code unhashable. An absolute item is used as it is. An item that is not there (`ENOENT`, `ENOTDIR`), is a folder or is a device (`/dev/null`) is plain text. An item outside the plugin folder that is a FIFO or a socket makes the code unhashable: a program reads what it feeds, and no real plugin passes one (`decision:2026-11-23-plan33-argv-fifo-unhashable`). Any other failure to resolve it (`ELOOP`, `ENAMETOOLONG` from a short path whose real path is long, `EACCES`) makes the code unhashable: `open` and an interpreter may still reach the file. A file inside the plugin folder is covered by `folder_sha256` and is not repeated. A ninth distinct file makes the code unhashable.
- `interpreter` is set when `command[0]` has a base name `sh`, `bash`, `zsh`, `python`, `python3`, `node`, `ruby`, `perl`, `deno` or `bun`, or has the base name `env` (`/usr/bin/env`, `/bin/env`) followed by one of those names. `env` followed by anything else (an option such as `-S`, `NAME=VALUE`, another program, or nothing) runs a program from `PATH` that no record names, so the code is unhashable (`decision:2026-11-23-plan33-env-unlisted-unhashable`). The file is `command[0]` itself, or the first regular executable of that name in the `PATH` the caller passes (an empty or relative entry met before the hit, a trailing `:` included, makes the code unhashable, because env reads it against its working directory, which a record cannot name; an empty or absent `PATH` finds none). The row holds its realpath and SHA-256. An interpreter path that is there but is not a regular file (a folder, a device) makes the code unhashable. Two different interpreters in one plugin make the code unhashable.
- A file is read by streaming from a descriptor that was `fstat`ed as a regular file, never following a symlink at the last name. Caps: 4096 regular files, 4096 folders and 16 levels in the plugin folder, 512 MiB read in all for one subject: the folder's files, the argv files and the interpreter together (`decision:2026-11-23-plan33-total-hash-cap`). An argv file inside the plugin folder is not read twice. Past a cap the code is unhashable. A record path, a name or a need that is not UTF-8 is unhashable too, because it ends in the JSON file; a file name inside the plugin folder is only hashed, never written, so it may be any bytes.
- A check hashes again every time. It compares `kind`, `folder_sha256`, `manifest_sha256`, each `files` row's path and SHA-256, and the interpreter's path and SHA-256. It does not compare `size`, `mtime`, `needs`, `dev`, `trusted_at` or `path`. A mismatch is untrusted and nothing is deleted.

## Confirm

`decision:2026-11-12-plugin-approval-required-exit-5`, `decision:2026-11-12-hook-approval-required-exit-5`, `decision:g2-13`, log 010 H-9.4 and H-9.6.

- `plugin_trust_allow` hashes the code, builds the body, calls `env->confirm(callback_ctx, "plugin" or "hook", name, body)`, and only after a yes stores the record. It is the one function that writes `trust.json`. A NULL `env`, or a NULL callback, is no callback and never a yes.
- No callback: exit 5, `plugin_approval_required` (`hook_approval_required` for a hook), nothing recorded. A false return: exit 1, `plugin_approval_denied` for either kind, nothing recorded. The built-in plugin `hybrid` has no record and is trusted, and asking for it records nothing.
- The folder body is `Allow "<name>" to read your memories? It can send them off this Mac.`, then one need for each line. For an update, only the needs the old record lacks. The hook body is `Allow hook "<name>" to run <command>?`, where `<command>` is every argv item, separated by spaces (`decision:2026-11-23-plan33-hook-body-whole-command`). An item of only `A-Z a-z 0-9 @ % + = : , . / _ -` is shown as it is; any other, the empty one included, is in single quotes with each `'` written `'\''`, as a POSIX shell reads it. Story Weaver has the form to word (`decision:open-2026-11-23-plan33-hook-body-command-form`). Each value (name, command, need) is masked as it goes in (a control byte becomes `?`), so the only line breaks are the ones between needs, and a value cannot forge a line of the dialog.
- C-15: message `"<name>" has to be allowed first, and there's no terminal to ask you in. Nothing was installed.`, fix `Run '<command>' in your own terminal.` C-16: message `"<name>" wasn't allowed, so nothing was installed.`, fix `To try again, run '<command>' and type "<name>" to allow it.` `<command>` is what the caller passes. `diag_plugin_approval` prints them and returns 5 or 1. Name and command are echoed whole: the plain line masks control bytes and JSON escapes them.
- The CLI on a terminal uses `cli_confirm_typed_name`: it writes the body on the error stream (control bytes masked), then `Type "<name>" to allow it, or press Enter to cancel: `, reads one line, and returns true only when the line is exactly the name. Enter, any other text (a trailing space, another case, a CR), a line over 255 bytes and the end of input are false. With no terminal the CLI passes no callback. There is no `--confirm` flag.

## Check, enable and the warning

`decision:s-05`, `decision:g2-11`, `decision:2026-11-22-plan33-enable-guard-error`, `decision:2026-11-22-plan33-import-not-guarded`.

- `plugin_trust_check` and `plugin_trust_check_installed` return OK, untrusted (no record, or a hash differs), unhashable, unreadable or out of memory. Only OK is trusted. `plugin_trust_check_installed` loads `<data dir>/plugins/<name>/plugin.json`; a folder with no manifest, a manifest with an error, another name in the manifest, or a name that is not one path segment is unhashable. It checks a hook's record as a hook.
- `settings set plugin.<name>.enabled true` fails with the error `plugin_untrusted`, exit 1, nothing written, when the check is not OK. The message and fix are C-17's: `"<name>" changed since you allowed it, so it didn't run.` and `Run 'remember plugin trust <name>' to review the changes and allow it again.` Setting `false` and the built-in plugin are never refused. `settings import` can still write `true` for an untrusted plugin; the pre-flight check of plan 35 refuses to run it. An edit after trust does not turn a stored `true` off.
- The warning `plugin_untrusted` has the same two sentences (`diag_plugin_untrusted_warning`). Plans 35 and 36 print it and set `disabled_reason` `untrusted` in `index.json`.

## Open

- C-17 is false for a plugin that was never allowed (`decision:open-2026-11-22-plan33-never-allowed-copy`) and for an unreadable `trust.json` (`decision:open-2026-11-22-plan33-trust-json-unreadable-copy`); both print C-17 until Story Weaver words them.
- `hook_approval_required` prints C-15's words (`decision:open-2026-11-22-plan33-hook-approval-copy`).
- The line for each need, and a heading for an update, are not worded (`decision:open-2026-11-22-plan33-trust-body-lines`). The code prints one raw need for each line.
- The catalog fix of the four new error codes is a draft that no command prints, because each caller passes its own fix.
- A check and a run are two moments: plan 35 runs the argv of the subject it checked (its `manifest` bytes), never a fresh read of plugin.json. A file swapped between the check and the exec still runs; the hash cannot close that window.
- Known gap (`decision:2026-11-23-plan33-argv-fifo-unhashable`): an argv folder outside the plugin folder is text, so `python3 /ext/pkg` runs `/ext/pkg/__main__.py` unhashed; a path inside one item (`--require=/abs/x.js`, `-I/abs/lib`) is text too.
- A check reads up to 512 MiB each time. A fast path on size and mtime is plan 35's to add if the cost shows.
